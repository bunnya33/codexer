# 本地发布与打包

## Qt Agent 0.2.22：恢复每轮 Token 用量

修复 Qt 后台漏接官方桌面 IPC 的用量更新，导致控制端不显示输入、输出和缓存命中。逐条处理桌面变化后再合并界面更新，以累计差额统计整轮用量；实时预览和历史记录都读取原有 SQLite 用量库。保留已记录的数据，首次快照仅建立基线，中途接入、连接中断及计数重置标为部分统计，无法补算此前未采集的轮次。

同步补齐独立运行时的轮次开始/结束、重复通知及异常计数校验，附加用量后重新限制预览和历史消息大小。Windows Agent 升级为 0.2.22，服务器保持 0.3.36，控制端沿用现有显示，无需更新。构建、打包和实机结果见[验证记录](validation.md)。

## Qt Agent 0.2.21：首次连接快照初始化

修复 0.2.20 在读取服务器 `threadLimit` 时调用状态刷新、把尚未初始化的快照写成部分对象，导致首次连接缺失设备 ID、epoch 等必填字段并被服务器拒绝。连接前只保存目标上限，状态读取使用只读快照；随后按正常流程完整初始化。覆盖旧服务器未返回上限、默认 20、扩展 30 及关闭后重新连接的原生回归。

服务器保持 0.3.36，Windows Agent 升级为 0.2.21，沿用现有安装路径、配置、设备身份与加密登录。0.2.20 安装后遇到首次连接拒绝应升级此版，无需退出登录或重建设备。构建、安装及连接验收见[验证记录](validation.md)。

## 服务器 0.3.36 / Qt Agent 0.2.20：实时同步容量与新建会话断连

管理后台「系统设置」增加每台 Agent 的实时同步会话上限，默认 20、支持 1–30。设置持久化并通知在线连接器，离线连接器重连获取；降低时保留受保护任务并在空闲后收缩。完整目录与历史不受影响。新 Web 支持 30 个预览，服务器为旧原生 Control 提供兼容的 20 个预览与连续序号。

修复 Qt Agent 新建会话绕过容量检查，发送第 21 个实时预览触发旧 Relay `thread-limit`/`1008`。新建、watch 与最终提交共用检查；优先移出最旧安全空闲预览，全部受保护时在创建前拒绝本次命令，保持连接。服务器兼容协议范围内的旧 Agent 状态，不再因 21 个预览关闭连接。此次与 UTF-16 编码无关。

服务器包单独发布，Qt Agent 0.2.20 提供 Windows 安装版和便携版；完整的后台限额自动应用需要升级 Agent。生产部署、正式包与正在运行的客户端分别验收，不覆盖活动任务中的 Agent/Codex。

稳定版 [v0.3.36](https://github.com/bunnya33/codexer/releases/tag/v0.3.36) 对应 `1f62cb2`，[服务器发布流程](https://github.com/bunnya33/codexer/actions/runs/41169572595)通过完整回归、PostgreSQL、Go race、生产构建、独立程序和四目标打包，8 个正式附件齐全。Qt Agent 的 [Windows CI](https://github.com/bunnya33/codexer/actions/runs/41169572610) 编译、打包与迁移验收通过；本地安装版/便携版、校验文件及报告在 `release/agent-native-0.2.20`。

## macOS

在 Mac 执行 `npm ci` 后 `npm run package:desktop:mac`，输出 arm64/x64 DMG 和 ZIP。配置开启 hardenedRuntime 和必要 JIT entitlement。签名需要 `CSC_LINK`/`CSC_KEY_PASSWORD` 等维护者提供的开发者证书；notarization 使用 electron-builder 支持的 `APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID` 或其支持的 API key 配置。私密值只通过本地环境/CI secrets 注入。

未提供凭据时得到开发测试包，不能声称通过 Gatekeeper/notarization。真正发行前分别验证两种架构、登录项、Keychain、官方运行时和休眠重连，见 [macOS](mac.md)。本次不跨平台伪造 Mac 验收。

此版本统一更新 Relay、Admin 和 Web，需要配套 PC 连接器 `0.1.9` 或新版源码 Agent。RelayDesk `0.1.1` 加载服务器页面，更新服务器后刷新即可获得新界面；原生手机 App 需重新构建。服务器 Release 不附带 EXE、APK 或 IPA，不自动安装客户端。

本次没有新增数据库迁移。升级使用后台的准备、重启步骤，保留账号、数据和微信设置。验证范围见 [验证说明](validation.md)。

## 0.2.6 图片文件预览

图片文件链接直接打开可缩放的预览弹窗，保留下载按钮；超过 2 MiB 的图片也可直接预览，文本预览限制保持不变。支持 PNG/JPEG/WebP/GIF/BMP/ICO/AVIF/SVG，解码失败时显示错误并保留下载入口；EXE 和压缩包仍先确认下载。图片从 PC 按需读取，Relay 继续只转发、不存储文件。

统一服务器包更新 Relay、Admin 和 Web，网页更新后启用图片文件预览，原生 App 需重新构建。已支持文件协议的 PC 连接器无需为图片功能重新打包；Codex 的 `</D:/...>` 路径兼容修复仍需 PC 连接器 `0.1.8`。此服务器标签不发布新的桌面或原生手机安装包。

## 0.2.5 会话文件与微信通知开关

会话中的本地文件链接可点击，MD、TXT、JSON 等在客户端阅读，EXE、压缩包等先确认再下载。文件从在线 PC 分块获取，Relay 只转发，不缓存或持久化文件内容；按账号、设备、会话和已引用路径验证权限，并检查读取期间文件版本。

会话顶部新增默认关闭的“微信通知”开关。全局任务完成通知打开时通知所有已监听会话；全局关闭时只通知单独开启的会话。偏好按账号持久化，其他登录设备实时同步。

本地完整 292 项回归、46 个测试文件通过，类型、文档、服务器/Web/Admin/Electron 构建及 iOS/Android JS 导出通过。文件阅读与两个浏览器窗口的通知同步已用实际 PcAgent 和隔离 Relay 验证；系统下载落盘、原生保存/分享及真实微信投递的验证边界见 [验证说明](validation.md)。

统一服务器包更新 Relay、Admin 和 Web。**微信会话开关只需更新服务器；文件阅读还需更新 PC 连接器代码或重新打包安装。此标签不发布新的桌面安装包，也不更新原生手机 App。** 旧 Agent 会提示需要升级。新增通知偏好表由服务器启动创建，兼容原有账号和数据；从更早版本跨越快照迁移边界时继续遵循原备份要求。

## 0.2.4 Relay 优化与微信直接回复

微信收到完成通知后，可直接回复下一步要求，续做最近成功发送的通知或提交确认对应的会话。发送失败的通知不会改变默认目标；目标随绑定持久化，重启后保留。切换会话仍支持「继续 编号 下一步要求」。升级前的旧通知没有默认目标记录，可按编号提交一次要求，或等待新版完成通知。

Relay 按功能目录组织代码，设备快照按会话拆分存储，按设备串行执行、跨设备并行。广播按订阅索引发送并复用序列化结果，保留数据分批清理，管理员可通过 `/v1/admin/metrics` 查看关键指标。网页增加 WebSocket 建立和认证超时恢复，避免旧连接或延迟响应覆盖新连接。

源码同时修复 PC 连接器退出时关闭数据库过早的问题：等待正在执行的排队任务收尾，再关闭命令记录，避免晚到的执行结果访问已关闭的数据库。

本地完整 281 项回归、44 个测试文件通过，服务端与控制端类型、文档、Relay 格式检查和服务器/Web/Admin 构建通过；微信路由使用模拟接口验证。统一服务器包同时更新 Relay、Admin 和 Web，微信和 Relay 功能不要求更新 PC 连接器。

**升级前备份数据库和微信密钥。** 启动时自动迁移旧完整快照；迁移后的数据库不能直接交给旧版 Relay 读取。需要回退时，应一起恢复升级前数据库，操作见 [备份与迁移](operations.md)。

## 0.2.2 微信 ClawBot

在 Relay 服务器接入腾讯微信 ClawBot，每个普通账号独立绑定一个 Bot，汇总该账号多个 PC 的任务完成通知，并支持通过会话编号发送继续执行指令。Web 设置提供扫码、通知/回复开关、测试消息与解绑；不需要为了这项功能更新 PC 连接器。

新增微信绑定与消息队列表由服务器启动时创建。部署须保留数据目录中的 `weixin.key`，或固定配置 `RELAY_WEIXIN_KEY`，数据库与密钥一同备份。真实微信扫码及消息投递仍需部署后联调，使用与限制见 [微信接入](weixin.md)。
