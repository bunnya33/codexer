# 微信 ClawBot

微信接入在 Relay 服务器运行。每个普通 Codexer 账号绑定自己的一个微信 ClawBot，汇总该账号所有 PC 的通知。Codex 仍在 PC 上执行，微信指令经过设备归属、在线状态、epoch 和命令协议校验后转发。

采用腾讯公开的 [微信渠道协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)，兼容协议版本 2.4.9。扫码、长轮询和发送消息由 Codexer 实现，不需要安装 OpenClaw，也不经过公众号或第三方推送服务。

## 绑定

1. 更新并启动 Relay 服务器，登录 Web 或移动控制端。
2. 从会话列表底部的设置入口进入「微信 ClawBot」，选择「扫码绑定微信」。即使还没有 PC，也可以先绑定。
3. 用支持 ClawBot 的微信扫描二维码并确认授权。如微信要求验证码，填写手机上显示的验证码。
4. 绑定成功后，在微信里给 ClawBot 发送「你好」。收到帮助消息后，回到设置发送测试通知。
5. 可以分别关闭「任务完成通知」或「微信回复续做」，也可以解除绑定。解除后服务器停止接收和发送该 Bot 的消息。

绑定二维码五分钟过期；服务重启或重新获取二维码后需要重新扫码。同一 Bot 或同一扫码微信用户已经绑定其他 Codexer 账号时，服务器拒绝绑定。管理员账号不能查看或操作普通账号的微信绑定。

## 在微信中使用

- `帮助` / `你好`：显示用法。
- `设备`：查看所属电脑和在线状态。
- `会话` / `会话 2`：分页查看会话，每页十条，包含设备、项目、标题和独立编号。
- `继续 C1234ABCD 给登录页面增加验证码`：继续这个账号下的指定会话。空闲会话开始新一轮；活动会话提交排队请求。尚未被监听的会话会先尝试接入。

会话编号按账号、设备和会话持久化，多个项目或电脑同名也不会混淆。不会把没有编号的指令自动发送到最近一个会话。只接受扫码绑定的微信用户发来的私聊文字消息；其他发送者、群消息和非文字执行指令不会触发任务。审批、权限确认和交互提问仍使用 Codexer 控制端。

微信的「已提交」只表示指令已送往 PC，不表示任务已经完成。如果 PC 拒绝指令或结果未确认，会发送后续提示。设备离线时拒绝执行，不自动积压指令；超过五分钟的执行指令也不执行。收到重复微信消息时不重复下发，重启时不会自动重放已经领取但执行结果不确定的指令，请先核对实际会话。

## 完成通知与范围

当已监听会话的执行轮次从运行中变为 `completed` 时发送通知，包含设备、项目、会话编号和最后回复摘要。失败、中断、等待审批或提问不会标为完成。这里的完成表示本轮执行正常结束，具体交付结果仍以摘要与实际会话为准。

首次同步只建立基线，不发送旧任务通知。完成状态与待发送通知在同一个数据库事务保存；使用 Bot 绑定、设备、会话和轮次去重，断线重连或重复状态不会再次通知。通知队列按账号独立运行，最多保留 200 条待发送消息，失败退避重试，最多尝试十二次，超过一天的通知停止发送。网络异常重试沿用同一个微信客户端消息 ID；微信服务端最终去重行为仍需真实联调确认。

目前沿用 PC Agent 的监听范围：最多二十个最近或已固定的会话，快照每个会话保留最近两轮。不承诺覆盖所有历史会话、Agent 离线期间未上报的轮次，或很长断线期间已经移出快照的任务。

微信主动通知依赖有效的会话上下文，可能受到次数与活跃时间限制。公开客户端协议不是完整的服务端承诺；接入资料提到的「十次发送后需互动、每二十四小时需互动」需要用实际账号确认。收不到消息时先主动给 Bot 发一条消息，并检查设置中的连接错误和待发送数量。授权过期时重新扫码；账号禁用、密码重置或解绑会移除本地绑定，需要重新绑定。

## 服务端配置与备份

| 环境变量 | 用途 |
| --- | --- |
| `RELAY_WEIXIN_ENABLED` | 默认开启，设为 `false` 关闭；设置页面显示不可用 |
| `RELAY_WEIXIN_KEY` | 可选，64 位十六进制的 32 字节 AES 密钥 |
| `RELAY_DATA_DIR` | 未配置密钥时，自动创建该目录下的 `weixin.key`，Linux 权限为 0600 |

Bot token、微信上下文令牌和消息游标使用 AES-256-GCM 加密后存入数据库，附加认证数据包含账号 ID、绑定 ID 和字段名。API 不返回这些凭证，错误响应不包含微信响应正文。数据库中消息摘要沿用 Relay 数据存储边界，见 [安全说明](security.md)。

**数据库与加密密钥必须一起备份。** 使用外部 PostgreSQL 也必须保留 `RELAY_DATA_DIR/weixin.key` 或部署配置中的密钥。Docker Compose 已给 Relay 增加独立持久卷，容器替换不会丢失自动密钥。丢失或更换密钥后需解除旧绑定、重新扫码，不能通过数据库恢复明文凭证。

当前仍要求单 Relay 实例；不要用同一数据库和 Bot 凭证启动多个轮询进程。各账号分别维护轮询、发送队列和消息幂等状态，一位用户的微信故障不会阻塞其他用户或 PC 状态同步。

本地可通过模拟微信接口测试扫码、隔离、消息路由和通知行为；真实扫码、微信发送限制与投递结果必须在部署后用自己的微信验证。
