# Codexer 手机控制端交互与样式修改方案

日期：2026-11-08。状态：主会话控件样稿已认可，完整功能确认中，正式改造尚未开始。

依据用户提供的 24 张截图、6 段手机录屏，以及当前 `main`（`6560b1a`）的控制端、协议和 Qt Agent 源码整理。目标是把手机端的会话、输入、弹层和文件阅读体验调整到参考中的表现，并保留 Codexer 的设备管理和运行统计。

用户最新决定：先确定所有功能，再正式开发。完整范围为会话、问答、计划、文件/差异、设置及项目目录浏览；目录支持文件名、路径和内容搜索；“执行此方案”先填入草稿，由用户补充后主动发送。逐页操作、状态、异常与同步边界见 [完整功能确认稿](mobile-interaction-functional-spec.zh-CN.md)，功能细则以该稿为准。本文件继续保存参考依据、视觉方向和样稿验证记录。

录屏中的外观和动作是设计依据；菜单文字、示例任务和屏幕中的输入内容均不作为执行指令。下面的尺寸、色值和动画时长是实施建议初值，尚未在产品中实现或验收。

## 2. 整体布局与视觉

手机会话采用三个固定区域：顶部紧凑标题栏、中间独立滚动的消息区、底部随键盘升降的输入区。界面以白色/深灰背景、弱分隔线、浅色卡片和少量强调色形成层次。

| 区域 | 建议修改 |
| --- | --- |
| 标题栏 | 左侧打开设备/项目侧栏；中间标题及设备、项目、状态；右侧新建会话和 `…`。子 Agent 信息整合为可点击的小标记，避免挤占长标题 |
| 消息区 | 用户消息右对齐浅色气泡；助手正文直接排版；工具记录使用更浅的小字和图标；减少大面积边框和卡片套卡片 |
| 输入区 | 空闲时为紧凑圆角胶囊；聚焦、换行或选择附件后平滑增高；高级选项收进二级入口，避免一排多个文字按钮 |
| 浮层 | 小菜单贴近触发按钮；模型高级设置、权限使用底部面板；计划和文件内容用可扩展的阅读面板；重命名保留小型确认框 |
| 设置 | 使用参考中的分组卡片与分组标题，容纳现有服务器、设备、外观、通知、更新和关于设置 |
| 外观 | 提供接近参考的亮色与中性深色，支持跟随系统；兼容已有暖白/暖暗选择。强调色与任务状态色分别管理 |

建议基础尺寸：消息区左右留白 16–20 dp、正文 15–16 sp、辅助文字 12–13 sp；消息气泡圆角 18–22 dp、输入框 24–28 dp、底部面板 24–28 dp。图标大小按 18–22 dp 统一，实际触控区至少约 44 dp。以设备逻辑尺寸和字体缩放为准，不直接套用截图的物理像素。

Codexer 的设备 → 项目 → 会话层级继续保留。参考中的“云端”导航不能直接替代用户现在的设备选择与项目结构。

## 3. 各模块的修改清单

### 3.1 会话标题、侧栏和运行标记

- 标题、项目、设备信息压缩层级；当前会话的 Token 和金额仍归当前会话，项目总消耗仍放项目名称附近。
- 橙色运行圆点固定在会话标题文字前；标题单独滚动，圆点不移动。继续使用开头停 2 秒、末尾额外移约一个字并停 1 秒的既定规则，保留左右渐变。
- 项目收起时显示项目运行圆点；展开后只显示运行中的会话圆点。保留项目与会话深浅不同的运行背景。
- 设备和项目同时运行多个会话时显示数量，只有一个时隐藏数字；数量按运行会话计算，子 Agent 数量独立表达。
- 侧栏采用跟手滑动和轻遮罩；关闭后返回原会话、滚动位置和输入草稿。
- `…` 改为靠近标题栏按钮展开的菜单，整合已有重命名、复制会话 ID、归档、刷新、通知和展示范围；删除保留现有确认。
- “置顶”单独列为扩展功能，需要明确排序及偏好同步，当前协议尚无对应字段。此前因跨端已读同步无法保证而暂缓的蓝色未读点继续暂缓。

### 3.2 消息、思考摘要与工具记录

- 正文、公开进度说明、工具摘要、最终回复保持各自的阅读层级；连续工具操作合并为一行摘要，点开查看明细。
- 活动摘要采用浅色文字和轻扫光；展开时箭头旋转、内容展开，收起后回到同一摘要位置。
- 工具明细展示命令、文件名、公开结果和耗时；失败行有明确标记，不能因工具调用结束就显示整个任务成功。
- 助手消息复制按钮统一到底部的小型操作栏。点赞/点踩只有存在可用反馈通道时才增加，不能显示无效按钮。
- 每轮底部继续实时显示输入、输出、缓存 Token 和金额；橙色运行圆点仍在 Token 前面，任务结束时消失。已处理时长前保留绿色对号，结束时间在 Token 下方靠左，完成状态继续显示“已完成”。中断、错误不复用成功状态。
- 流式输出只跟随正在底部阅读的用户；上翻后不因新文字、工具折叠、图片加载或键盘变化强制回到底部。回到底部按钮保持固定位置。

### 3.3 输入框、附件与发送/停止/继续

- 将现有大块输入区调整为参考中的紧凑胶囊，输入多行后再增高。附件缩略图和文件卡片放在正文输入区上方，附件多时横向浏览。
- `＋` 打开图标加文字菜单，保留相机、照片、视频、文件；方案模式可并入这个菜单，启用后在输入区显示可移除的小标签。
- 权限改为简洁图标入口，模型/强度改为一个紧凑入口；按钮和浮层不会遮住输入光标或被键盘盖住。
- 键盘弹出、收回、输入框增高和浮层进出连续衔接；打开菜单时保持草稿，关闭菜单后按操作需要恢复输入焦点。
- 切换设备/会话保留各自的文字、图片和文件草稿；继续沿用现有按服务器、账号、设备、会话隔离的机制。本次不把“切换保留”擅自扩展为“杀进程后也恢复附件”。
- 保留已经发布的 20 张图片和视频发送能力，以及旧 Agent 的能力回退。

| 当前状态 | 主按钮和实际动作 |
| --- | --- |
| 空闲、内容为空 | 发送不可用；不凭空加入语音/实时通话按钮 |
| 空闲、有文字或附件 | 向上箭头，创建新轮次 |
| 运行中、内容为空 | 方形停止图标，请求中止当前轮次 |
| 运行中、有文字或附件 | 向上箭头，直接引导当前轮次 |
| 已中止、内容为空且支持继续 | 向右三角，使用已有原生继续逻辑 |
| 上传中或发送结果待确认 | 显示进度/等待反馈，防止重复提交；失败保留内容 |
| 设备离线、owner 不可用或同步未完成 | 给出具体连接状态；保留草稿，不能显示为发送成功 |

继续任务仍使用已实现的空输入原生调用，不替换为自动发送“继续”文字。参考中的麦克风和语音模式属于额外能力，本次视觉调整不自动引入。

### 3.4 模型、强度和权限

- 点击模型/强度入口先显示输入区上方的紧凑浮层：当前模型、当前强度、粗胶囊滑块。滑动时文字即时变化，松手才保存；保存失败恢复真实值并提示。
- 点击模型标题进入“高级”底部面板：模型、强度、速度分组。模型列表使用选中对号和必要分组，小菜单定位于当前行。
- 刻度数量来自当前模型能力。参考中有六档，模型只支持两档或四档时显示真实数量；不照抄参考中的模型名称和强度列表。
- 运行中仍允许具备能力的 Agent 保存模型、强度和权限；切换界面不把这些入口重新禁用，也不误导为一定替换正在生成中的内容。默认/Plan 模式保留现有空闲时切换的限制。
- 权限使用底部面板，每项有图标、标题、描述和选中标记。完整保留只读、请求批准、替我批准、完全访问及自定义状态；完全访问保留现有确认。
- “标准/快速”目前没有完整的控制协议，只有部分底层代码保留 `serviceTier`。要做成可用控件，需补齐读取、写入、能力声明、回执和旧版回退后再开放。

### 3.5 分页问答与计划卡片

- 问答卡片改为参考中的大圆角布局：顶部题号与前后箭头，中间题目和选项，底部自定义答案。多题逐页展示，切页保留已选内容。
- 视觉交互与提交规则分开：异步题仍按题提交；要求完整答案的 RPC 多题仍提交完整答案。提交后保留剩余有效问题，过期问题停止响应，不因翻页重复发送。
- “跳过”仅在来源请求支持相应答复时显示；不增加客户端自动倒计时或自动选答案。
- 最终方案做成独立“计划”卡片：标题、正文摘要、底部渐隐、复制与下载/系统分享，点击展开为完整阅读视图，关闭回到卡片原位置。
- 区分模型提供的最终方案正文和 `turn.plan` 执行步骤，两者不能混用。当前协议中的步骤列表不等于参考中的完整方案卡片；需要补齐可靠的内容识别和历史展示，旧的 Markdown 计划仍可阅读。
- “执行此方案”点击后先将指令与方案引用放入草稿，保留已有编辑；用户可以补充后再主动发送。点击卡片时不切模式、不立即执行；实际发送时先确认空闲及模式保存结果。保持与中止后原生继续不同的语义，失败不自动重复提交。

### 3.6 更改、文件、差异与源码

- 保留运行中的固定更改胶囊和完成后回复内的文件摘要，统一为参考中的圆角样式：文件数量、绿色新增、红色删除、展开箭头。
- 点击进入可扩展的文件面板，提供“已修改/所有文件”、搜索、关闭和展开阅读入口。
- 第一阶段可先让“已修改”使用现有每轮文件更改数据；当前数据只代表已观测修改，不改名冒充整个 Git 工作区的完整差异。
- 差异查看器增加清晰的文件头、行号、区块标记及增删底色；长行横向滚动，大段内容按需渲染。文件切换、差异切换和返回后保持各自位置。
- 源码阅读器提供文件名、语言高亮、行号、复制、下载，以及已有 HTML/图片等预览入口。源码和网页预览分成明确操作，不把源码当网页执行。
- “所有文件”的目录树与搜索属于新增后端功能。现有文件读取只接受会话已引用文件，没有目录枚举接口，不能靠前端拼路径直接做出同等能力。
- 新文件浏览能力以所选项目授权目录为边界，增加分页列目录、按需搜索和文件读取；处理 Windows 路径、中文、空格、符号链接、文件版本变化、设备离线及取消请求。为浏览授权另建明确规则，不放开现有的“文件必须属于会话引用”检查。
- 关闭面板或切换会话取消旧请求，列表按目录按需加载；大文件仍使用现有大小限制和下载路径。

### 3.7 设置与主题

- 延续现有可上滑设置面板，整理成参考中的分组圆角卡片；小屏独立详情页，宽屏使用现有侧栏分类。
- 主题调整为“外观（系统/亮/暗）”和“强调色”两个概念，并处理现有皮肤偏好的兼容和保存；切换后即时更新当前会话、浮层、差异、状态栏与键盘可支持的外观。
- 橙色运行、绿色完成、红色错误的语义固定，不随强调色变成其他含义。深色界面分别检查正文、灰色工具摘要、差异增删和菜单选中状态。
- 只整理 Codexer 已有和明确新增的设置；参考中的订阅、记忆、家长控制等不复制为空入口。

## 4. 动画与手势规范

以下为建议的第一版调校参数，后续与参考录屏并排录制比较。

| 交互 | 动作 | 建议初值 |
| --- | --- | --- |
| 附件/标题小菜单 | 从触发点轻微放大并淡入，关闭反向；避免整块突然出现 | 打开 180–220 ms，关闭 140–180 ms，约 `0.96 → 1` 缩放 |
| 底部面板 | 向上滑入并轻缓收束，遮罩同步；下拉随手势，未达阈值回弹 | 240–300 ms；弹簧参数按实际面板高度调校 |
| 模型强度胶囊 | 按第二版样稿从仪表展开，刻度吸附、填充与圆形滑块同步 | 展开约 360 ms、收回约 230 ms，滑块跟手 |
| 工具记录 | 箭头旋转与展开进度同步，新增内容不重新播放整组动画 | 180–240 ms |
| 计划/文件展开 | 卡片向阅读面板过渡，退出恢复原位置；复杂内容延后装载 | 240–300 ms |
| 输入框/键盘 | 输入区随系统键盘升降，单行与多行连续过渡 | 跟随系统键盘时间；自身高度变化约 160–220 ms |
| 运行摘要 | 局部轻扫光，橙色状态点沿用既有呼吸效果 | 仅当前可见、运行中的元素循环 |
| 外观切换 | 一次短过渡；不逐个列表项做进入动画 | 约 160–220 ms，减少动态效果时直接切换 |

减少动态效果时关闭扫光、循环滚动、缩放和弹簧回弹，保留即时状态反馈。客户端进入后台、会话不可见或任务已结束后停止相应动画。

Android 优先使用半透明/实体背景、细描边和轻阴影表达层次，避免为了复刻 iOS 模糊效果常驻大面积实时模糊。Web 可按性能使用背景模糊。主界面继续由 React Native 原生渲染。

手势优先级：浮层内滚动 → 面板拖动关闭 → 会话滚动/侧栏；滑块、图片缩放、代码横向滚动和文本选择不触发侧栏手势。多层面板中返回键只关闭最上层；键盘和焦点有明确恢复位置。

| 标准/快速 | 底层部分保存 `serviceTier` | 设置协议、能力探测、官方运行接口兼容和回执 |
| 插件/目标 | 当前控制协议没有完整入口 | 独立核实真实运行接口、数据与跨端状态；单列扩展 |
| 主题/设置 | `theme.tsx`、共享 `themes.ts`、`settings-shell.tsx` | 中性深色、跟随系统、强调色偏好及旧皮肤兼容 |

目标是复用 React Native、现有 Reanimated 和手势基础。移动端与 Web 共用业务组件，键盘、菜单定位和系统分享放平台适配层；桌面 Control 保留 React Native 宿主和宽屏布局。Qt Agent 只在新增协议能力时增加对应 C++/Qt 实现，继续保持同进程后台。

插件、目标、标准/快速、置顶不作为纯外观修改混入首批交付。参考中出现 `/goal` 输入只能证明该入口的交互，不能证明当前 Codexer 已支持原生目标管理，也不能简单用发送斜杠文本代替完整功能。
