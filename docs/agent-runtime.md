# Agent 重启与 Codex 运行时刷新

## Agent 0.2.17：原生后台

Windows 连接器的界面及后台统一为 C++/Qt，单个应用进程，不再启动 Node 后台。官方 Rust Codex app-server 仍按需作为独立子进程运行，执行模型任务及工具；其内存应在连接后采样中单独列出。服务端仍为现有 Go 版本，Control 不在此次后台迁移范围。

原生后台沿用登录/设备身份、旧加密凭据、SQLite 命令去重与队列，支持桌面 IPC 与 app-server 两种会话路径。旧版未确认命令不自动重发；结果未知的消息、审批和队列继续保守处理。断开远程连接保留本机任务，网络等待期间撤销远程授权后不执行后续副作用。图片源登记限制为 64 MiB，更新文件分块哈希校验。

## Agent 0.2.16：空闲写入者释放与桌面交接

Qt 连接器在「会话与运行时」和托盘提供「释放空闲会话」。每 5 秒检查一次自身成功 `thread/resume` 或 `thread/start` 的写入者，最近使用至少 5 秒后可自动释放；显式操作可立即检查。释放前通过 `thread/read` 再确认所有自身写入者空闲，然后初始化替代 app-server 并停止旧服务来释放写入锁，保留会话观察、历史、文件、有效设置与设备身份。当前 Codex 的 `thread/unsubscribe` 实测仅取消订阅，不能释放 writer，因此不把它当作释放成功。未保存新会话、运行任务、正在执行命令、审批/回复请求、刷新及活跃子任务会延后；不调用删除、归档或会话回滚。初始化替代进程失败时保留原服务。

当独立后台被明确拒绝 `thread/resume` 且错误为 active writer，自动模式会重新发现兼容的官方桌面 owner，确认后转交同一未发送指令。只有明确拒绝恢复的错误可交接；`turn/start` 超时、未知结果及显式独立后台模式不自动重发，避免重复消息。桌面不可用或协议不兼容时显示 `thread-writer-busy`。刷新运行时不能释放官方桌面或其他 CLI 仍持有的写入者，更不能把正在执行的任务“重置”成空闲。

此能力随 Agent 核心更新生效，Qt 本机手动入口随新包交付。Control 的错误中文说明在共享源码更新，Web 仍需服务器重新构建部署；此次不新增远程强制抢占接口。测试不操作用户真实会话的写入权。

Agent `0.2.15` 的托盘菜单增加「重启 Codexer Agent」和「刷新 Codex 运行时」。Control 网页端随服务器 `0.3.30` 在「设置 → 服务器与设备」增加当前 PC Agent 的刷新入口。Android、Windows/macOS 原生 Control 共用此界面源码，已安装客户端需另行构建升级。

## 重启 Agent

完整退出后台服务后通过 Electron 的 relaunch 重新启动 Agent。沿用退出确认；任务运行中会明确提示重启将停止 Agent 启动的本机任务，默认保留在后台。取消时不重启。保留配置、设备身份和系统加密登录，原来已连接时恢复连接；不修改自动连接偏好。便携版从原始便携 EXE 重启，开发与隔离测试保留启动参数。

## 无需退出 Agent 的刷新

修复 Worker 将自动发现的 Codex 路径写回固定路径环境变量的问题。自动模式在每次创建后台服务时重新发现运行程序；用户明确选择的路径或外部显式配置仍保持优先。Windows 自动发现优先选择带 `codex-code-mode-host.exe` 的完整安装，兼容旧版只有主程序的安装。

每 15 秒检查已使用运行时的路径、主程序和配套工具的文件标识。检测到更新后，在安全空闲时切换 Agent 管理的 app-server 子进程。先确认替代进程初始化成功，再停止旧进程并恢复观察、有效会话设置和队列；初始化失败时保留旧服务并记录脱敏诊断，后续重试。Agent 界面、Relay 连接、设备 epoch、登录及官方桌面 IPC 连接保持。

主动刷新在程序路径未变化时也能重建空闲后台服务。运行任务、正在启动的任务、待审批/回复请求、活跃子任务及尚未持久化的新建空会话均会延后；任务或新会话完成保存后，定时检查继续执行。刷新不抢占官方桌面或其他 CLI 的 writer。由官方桌面自己承载的任务仍由其管理，刷新 Agent 的后台服务不能代替修复官方桌面或解除其他进程的写入占用。

## 远程刷新与边界

远程入口仅对已选择、在线且上报 `runtimeRefresh` 能力的 Agent 启用。允许后台运行时本身不可用但 Agent 仍在线时发起检查；Agent 整体离线或退出时无法远程恢复。

`runtime.refresh` 指令没有路径、程序参数或权限字段。沿用现有账号与设备授权、设备 epoch、指令有效期、持久化结果和重复提交去重。服务器对旧 Agent 拒绝该操作，Agent 对成功切换设置 15 秒冷却，重复点击不连续重建服务。不增加远程退出/重启 Agent、任意程序执行或权限扩展接口。

Control 显示「已刷新」「无需切换」或「已安排」的真实确认结果。「已安排」仅表示已接受延后请求，不表示此刻已完成切换。切换期间会话状态可能短暂重新加载；已完成刷新可在 Agent 诊断日志查看 `codex-runtime-refreshed`。如运行任务已因旧工具路径报错，可先让任务正常结束，或使用已有停止任务入口，再刷新和重试。

升级顺序为服务器/Web、Agent；原生或 Android Control 另行升级对应安装包。旧服务器不识别新指令；旧 Agent 不显示可用能力，按钮会禁用。
