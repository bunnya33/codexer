# 发送项目到其他设备

服务器 0.3.59、Qt Agent 0.2.36 和共享控制端界面新增项目传输。接收设备先保存文件、登记项目；用户之后自行切换设备并继续操作。接收过程不创建开发会话、不发送模型请求、不安装依赖，也不运行项目脚本。

## 使用

1. 两台电脑的 Codexer Agent 登录同一账号并连接。接收电脑在 Agent 设置中授权项目父目录。
2. 打开源项目「… → 发送到其他设备」，选择接收设备、父目录和一个新的文件夹名称。
3. 选择是否保留本地 Git 数据、是否包含本地配置和数据库，并调整排除目录。可填写交接说明。
4. 点击「生成快照并预览」。Agent 等待当前任务空闲后生成快照；控制端显示文件数、大小、目标路径和排除项示例。
5. 点击「确认发送」。关闭弹窗后传输继续，侧栏底部「项目传输」可重新查看、确认或取消任务。
6. 「项目已接收」表示文件已经校验、保存并登记到接收设备的项目列表。用户可以稍后选择该设备和项目。

文件已落盘而项目登记暂不可用时，显示「项目已保存，正在登记项目列表」及真实保存路径。Agent 自动重试登记；也可以在目标电脑添加该已有目录。接收文件不依赖模型任务或开发会话。

## 快照内容和限制

- 支持没有 Git 的目录；直接复制当前工作目录中的文件，包括未跟踪、未暂存和已暂存修改，不创建提交或推送。
- 启用 Git 数据时，复制项目内普通 `.git` 目录，保留本地提交、分支、索引与工作目录状态。Git 元数据内部不套用普通依赖和数据库排除规则。
- Git worktree 的 `.git` 指针、外部 common dir/objects alternates、显式 `core.worktree` 暂不支持携带历史。可关闭 Git 选项传送当前文件；不修改原仓库。
- 默认排除所有层级的 `node_modules`、`.venv`、`venv`、`__pycache__`、`.cache`、`.next`、`.nuxt`、`.turbo`、`.gradle`、`build`、`dist` 和 `.local` 目录，可在发送前编辑。这是明确的目录名列表，不使用 `.gitignore` 隐式过滤必要文件。
- 本地配置选项默认关闭，排除 `.env` / `.env.*`（保留 `.example`、`.sample`、`.template` 示例）和 `.db`、`.sqlite`、`.sqlite3` 及相应 WAL/SHM 文件。启用后按当前磁盘内容复制；运行中的数据库应先停止写入。
- 保留二进制、零字节文件、空目录和可执行位。只包含已经保存到磁盘的内容。
- 多根项目分别放入 `root-1`、`root-2` 等子目录，登记原有多个项目根。可选交接说明写入独立的 `CODEXER-HANDOFF-<随机 ID>.md`，不覆盖用户文件。
- 单次快照最多 4 GiB、100,000 个文件和目录、20 个项目根。协议版本 1 使用有界内存的二进制快照，不压缩整个项目进内存。
- 符号链接、Windows Junction、特殊文件、跨平台非法文件名和仅大小写不同的路径会明确失败，避免静默漏传或写到目录之外。可调整排除项或文件结构后重发。
- 打包期间暂缓源项目新的远程写操作和自动发送队列，并核对源文件内容、目录清单与目录身份。外部写入导致变化时要求重新生成快照。

## 传输与恢复

控制端只提交元数据并显示状态。文件由源 Qt Agent 经 Go Relay 中转到目标 Qt Agent，手机无需保存项目副本。任务、偏移和暂存数据持久化在 Relay 数据目录的 `project-transfers` 中。

块大小固定 512 KiB；上传根据服务器确认偏移续传，下载根据目标缓存长度继续。每个文件和整个快照均进行 SHA-256 校验。源快照保持独立，传输期间继续修改源项目不会改变已经确认发送的快照。

目标先写入授权父目录中的 `.codexer-incoming-<任务 ID>`，校验后通过同目录重命名保存为最终目录。最终目录存在时拒绝覆盖。进入保存阶段后不再接受取消；取消不能撤销已经保存的项目。私有接收回执绑定任务、快照校验值和目录身份，重启后可识别已经保存的目录，避免重复写入。

源与目标均重新验证账号和设备归属，Agent 凭据限定本设备。接收时还验证本机当前授权父目录和逐级目录身份。密码重置、退出和设备撤销沿用既有鉴权边界。项目传输不复制 Agent 登录凭据或设备身份。

创建后 24 小时到期，过期任务停止授权并清理服务器暂存文件。完成、失败或取消时清理大块暂存数据；Agent 定期清理过期私有快照和可确认归属的接收临时目录，保留最终项目。每账号最多 2 个未结束任务，全局最多 4 个，服务器最多预留约 16 GiB 的项目载荷。列表优先返回未结束任务，避免旧任务被历史记录挤出。

## 接口

控制账号：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/v1/project-transfers` | 按调用方生成的 UUID 幂等创建准备任务 |
| GET | `/v1/project-transfers` | 当前账号的任务及进度，最多 100 条 |
| POST | `/v1/project-transfers/{id}/start` | 确认发送已准备的快照 |
| POST | `/v1/project-transfers/{id}/cancel` | 保存开始前取消 |

设备专属会话，必须同时提供 `Authorization` 和匹配的 `x-device-id`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/agent/{deviceId}/project-transfers` | 当前设备相关任务 |
| GET | `/v1/agent/{deviceId}/project-transfers/{id}` | 核对状态与恢复偏移 |
| POST | `/v1/agent/{deviceId}/project-transfers/{id}/status` | 源准备结果、目标进度和保存结果 |
| PUT | `/v1/agent/{deviceId}/project-transfers/{id}/chunk?offset=N` | 仅源设备上传固定块 |
| POST | `/v1/agent/{deviceId}/project-transfers/{id}/uploaded` | 核验快照并允许目标接收 |
| GET | `/v1/agent/{deviceId}/project-transfers/{id}/chunk?offset=N` | 仅目标设备下载固定块 |

目录能力使用可选 `catalog.projectTransfer: true`，旧 Agent 保持其他功能。旧服务器的 API 404 显示升级提示。Web 需更新服务器；原生 Control、Android 需分别重新构建安装，源码共享不代表已安装客户端自动获得界面。Qt macOS 需要单独原生编译和实机验收。
