# 远程查看 Agent 资源占用

控制端左侧会话列表顶部的设备卡片，在在线状态下方显示 Agent 本身的 CPU 和常驻内存。点击资源行打开「Agent 运行状态」，查看 Agent 与它直接启动的 Codex app-server 各自的 CPU、常驻内存、PID、运行时长和采样时间。Windows 额外列出私有提交。网页、iOS／Android 和 Windows／macOS 原生控制端复用此共享界面。

CPU 按整机总算力 100% 计算，使用进程累计 CPU 时间差除以单调时钟间隔和逻辑处理器数。第一次采样以及超过 30 秒没有采样时先建立基准，随后计算短区间占用。内存使用 MiB／GiB，Windows 对应工作集，macOS／Linux 对应 RSS；无法读取的值保持空值。仅统计 Agent 与它直接持有的 Codex app-server，官方桌面程序和 app-server 运行的命令／工具进程另计。

侧栏可见且控制端处于前台、设备在线、实时连接正常时，每次完成后间隔 5 秒读取。首次 CPU 采样后间隔 1 秒补读，失败后间隔 10 秒重试，单一界面不叠加请求。关闭侧栏、切换设备／账号／服务器或退后台会取消请求和后续计时，迟到响应不更新界面。详情沿用同一次采样。离线、断线、读取失败或超过 15 秒没有更新时，缓存数字标明「上次采样」；时效依据控制端接收时间计算，避免设备时钟不同导致误判。

鉴权的 `GET /v1/devices/{deviceId}/resources` 在现有 Agent WebSocket 上转发 `resources.request`／`device.resources`。Relay 不保存资源采样、会话事件或命令记录，不扫描进程、不增加后台采样任务。响应、超时、HTTP 取消、设备断线及会话撤销均释放待回复项，单设备最多 4 项、全局最多 64 项，8 秒超时。仅授权设备所属账号可读，Agent 凭据不能当作控制端凭据使用，返回前再次核对会话和设备权限。

Agent 使用系统原生 API 读取自身以及当前 RPC 对象持有的子进程，不扫描全部进程、不启动 shell 或外部监控程序。相同进程组合在 1 秒内共享本机缓存，只保留最多两个进程的上次计数和一份响应。进程启动身份变化或计数回退时重新建立 CPU 基准，防止 PID 复用或运行时重启产生错误占用。Windows 使用进程时间与内存 API，macOS 使用 `proc_pidinfo`，Linux 读取对应 PID 的 `/proc` 数据。

此功能需配套更新 Agent、Relay 和使用的控制端；Agent 与 Relay 通过 `resources` 能力协商，旧服务器不会收到新消息。旧 Agent 或旧服务器显示需要更新并停止当前轮询，重新打开侧栏或恢复连接后重新检查。Mac／iPhone 原生构建与真机验收另行记录，Windows 编译和网页预览不能代替。
