# Mac Agent 会话同步

2026-11-14，手机会话停留在旧回复，新消息、实时内容及任务结束状态长时间没有更新。桌面本地会话日志已记录当前任务开始，Agent 的状态文件仍一度显示空闲；独立只读 IPC 观察器随后连续收到 `thread-stream-state-changed` 快照和补丁，而 Agent 更新序列增长缓慢。旧 Agent 的三秒采样中，后台 tick 栈的 2,142 个样本有 2,087 个停在其他会话的 owner discovery 等待。

## 原因和修复

Qt Agent 收到 IPC 更新时，原先只把会话 ID 放入后台待刷新集合。该集合还承载目录扫描、owner discovery、历史读取和子代理元数据查询；每个 tick 只取一个会话，并可能同步等待运行时。无序集合反复添加待刷新会话，使最新消息的发布等待不可预测。手机或 Relay 重新订阅拿到的仍可能是 Agent 的旧快照，因此仅给手机增加刷新不能解决这段阻塞。

Agent 0.2.40 将已收到的桌面状态按 100ms 窗口合并发布。发布过程只使用缓存和本地记录，不查询运行时；运行时等待所泵送的事件循环也能发送这些状态。新消息、最终回复、请求和 active／idle 状态走同一路径。后台元数据工作使用去重的先进先出队列；元数据等待结束后检查桌面状态版本、来源和接收时间，防止把等待前的旧状态写回。

桌面订阅增加只读恢复：收到接管者离线通知立即标记不可用；超过 30 秒没有接收状态时，在后台刷新该会话时重新订阅请求快照，等待快照超过 3 秒则在下次刷新时重新发现接管者。阈值用于恢复触发，不是端到端延迟上限；刷新仍受后台工作和网络影响。恢复不会调用中断、重放消息或猜测任务是否结束。

本地 `status.json` 的每个会话增加 Agent 会话 revision、桌面 revision／接收时间以及最近两轮的 ID、状态和条目数量，便于判断桌面接收与发布是否同步；不记录消息正文或凭据。Relay 和手机协议不变，此修复无需更换 IPA。

## 验证

隔离测试使用真实 Qt 本地 IPC 和 WebSocket，在另一会话的 owner discovery 等待期间注入消息及任务完成补丁。旧代码无法发布运行状态，修复后实际收到包含新消息和最终回复的 WebSocket 事件，且写命令仍保持排队。另覆盖静默订阅、初始快照缺失、接管者替换／离线、旧来源补丁拒绝，以及慢速元数据读取不得覆盖新状态。

macOS arm64 已实际原生编译。Qt 后台 130 项通过、2 项需要显式外部夹具的测试跳过；界面 18 项通过、1 项截图条件跳过；338 个跨语言协议案例通过。隔离真实 writer 检查通过，没有发送模型任务。DMG／ZIP 验签、依赖检查、解包及挂载比对通过；本机安装、原身份／登录／设置及真实 Relay 控制页持续接收消息复核通过；用户反馈手机恢复。35 秒只读观测中，本机发布延迟中位数为 121.93ms，范围 62.02–515.05ms；这不是手机延迟。详见 [验证记录](validation.md)。Windows／Intel 尚未为本版本编译或实机验证。

## 复测

1. Mac 保持 Codex 与 Agent 在线，手机打开同一会话。
2. 从手机发送消息，观察消息是否出现、任务是否变为进行中，以及回复是否持续出现。
3. 自然等待任务完成，确认手机显示已完成；不要通过中断触发刷新。
4. 若仍延迟，保留两端时间与会话 ID，对照本地状态文件中的桌面接收时间、revision、最近轮次及 Agent 序列。只有实际经过手机网络和界面的观测才能作为手机延迟结果。
