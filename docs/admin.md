# 管理后台

React + Vite 管理控制台随 Relay 和 Web 一起部署，访问同一服务器的 `/admin/`。侧栏含仪表盘、控制端账号、后台管理员、客户端更新、服务器日志和系统设置；顶部显示当前管理员，手机宽度使用抽屉导航。传统侧栏布局使用原有蓝色主色、白色卡片和浅灰背景；版本状态保留绿色/橙色语义提示。

## 两类账号

| 类型 | 登录位置 | 权限 |
| --- | --- | --- |
| 后台管理员 | `/admin/`，`/v1/admin/auth/login` | 管理账号、登录策略、查看服务状态、服务器更新、发布和删除客户端安装包 |
| 控制端账号 | Web `/`、App、PC Agent | 查看和控制同账号登录的 PC |

两类账号独立，同名账号允许使用不同密码，不能互相登录。后台不读取任务内容，也不能申请控制端的 WebSocket 票据。首次管理员沿用安装器生成的账号密码；已有管理员不会在重启时被环境变量覆盖。

旧版若曾使用管理员账号连接 PC，升级后该账号不能继续用于 Agent。创建一个控制端账号，再在 PC 连接器和 Web/App 登录它；旧设备与内容仍保留，不自动转移到新账号。

## 页面与操作

- 仪表盘显示真实账号数量/启用量、在线 PC、在线控制连接和进程运行时长。连接数不是用户数。
- 控制端账号：创建、搜索、重置密码、禁用。密码为 12–128 字符；改密/禁用立即撤销当前登录和 PC 会话，现有数据保留。
- 后台管理员：独立列表、创建、改密和禁用；服务器拒绝禁用当前管理员或最后一位有效管理员。重置自己的密码后需重新登录。
- 系统设置：离线登录超时 1 分钟至 30 天，默认 7 天，保存对已有控制端/后台登录立即生效。PC Agent 登录有效期独立设置，默认 7 天，可选 1–36500 天或永不过期（API 值为 0）。保存会调整仍有效的 PC 登录；已过期登录须重新登录，改密、禁用、注销和设备撤销仍可使其失效。
- 客户端更新 → 安装包管理：按平台、当前/历史版本筛选，查看文件名、版本、构建号、大小、上传时间、校验值及总占用。新上传保留上一版供手动清理；删除前确认，删除当前发布同时停止该平台更新，不自动回退。正在下载的安装包需稍后删除。上传与版本规则见[客户端更新](client-updates.md)。

旧“PC Agent · Windows 安装包”区域与控制端 EXE 下载入口已移除。Agent 安装包在“客户端更新”中选择对应的产品、平台和架构发布，由 Agent 自身检查更新。旧 `agent-releases` 目录和 API 保留兼容，已有文件不自动删除。

管理后台和控制端使用不同的 localStorage session key。离开页面时记录活动时间，在前台每 30 秒续期；网络错误保留登录，只有认证失效才清除。退出撤销当前登录。

后台修改管理员密码后，`relay.env` 中的首次密码不会自动同步；CLI 账号操作在旧密码失效时会提示输入当前管理员密码。执行 `sudo codexer password` 可同时同步数据库和受限配置。不要删除数据库恢复账号。

## 服务器日志

侧栏「服务器日志」记录设备连接和断开、协议拒绝、消息序号异常、存储错误、HTTP 5xx/限流及后台任务异常。按级别、分类、设备 ID 和错误代码筛选，手动刷新或加载更早日志。展开可查看连接 ID、设备/会话 ID、消息类型、字节数、序号、关闭代码、关闭发起方、连接时长、校验失败字段和规则；「复制诊断」复制该条结构化记录。

日志不保存任务正文、文件内容、令牌、密码、原始异常或远端自定义断连文本。协议记录里的动态字典键以 `*` 代替。连接 ID 将同一次连接的拒绝与断开关联；非断开的 `sequence-gap` 表示已请求重新同步。管理日志接口仅后台管理员可访问，不提供控制任务权限。

0.3.34 起，「复制诊断」支持 HTTP 环境的选择复制回退，结果显示在当前按钮旁；两种复制方式均失败时展开并选中只读诊断文本，可按 Ctrl+C 或长按复制，不必滚动到页面顶部寻找提示。

服务器在数据目录滚动写入 `server-logs.jsonl` 及 `.1`，每份最多 2 MiB，页面提供最近 2000 条。重启会重新读取仍在文件中的记录，较早记录可能因文件或条数上限被淘汰。写盘失败时继续保留内存记录，页面提示「未写入磁盘」，检查目录权限与空间。记录从更新启用后开始，不能恢复旧版本没有保存的拒绝原因。详见[运维说明](operations.md)。

## 左上角版本入口

当前版本徽标：确认无更新时绿色圆点，有新稳定版本时橙色呼吸圆点；无法检查或暂无可用版本时灰色。点击版本弹窗可重新检查、选择 Git tag、查看 Release 日志和执行当前步骤。

“系统设置 → 服务器更新”切换 Release 包或 Git tag 方式。Git 流程为“更新 → 构建 → 立即重启”，后两步分别确认；Release 下载准备好后也等待“立即重启 → 确认重启”。拉取或准备时旧服务继续运行。默认关闭的“自动准备稳定版本”只准备 Release，始终不会自动重启。

首次启用本次流程须重新运行新版 systemd 安装器，更新 root helper；旧 helper 会禁用后台安装按钮。Docker/其他部署仍使用外部更新流程。具体权限、失败重试、校验和回退见 [服务器更新](server-update.md)。

## 开发

`npm run dev:relay` 加 `npm run dev:admin`；后台开发地址 `http://127.0.0.1:5174/admin/`，Vite 默认代理到本机 Relay 8787，可通过 `CODEXER_RELAY_URL` 调整。生产构建 `npm run build:admin`，类型检查 `npm run typecheck --workspace @codexer/admin`。接口见 [API](api.md)。
