# Agent 内存与手机连接恢复

## 内存回收

Agent 0.2.40 对 Qt 原生后台增加以下约束：

- 只为已同步或正在创建、持有的会话保留 plan/diff。每个会话最多缓存最近两轮；diff 和计划内容沿用 live 视图的截断规则，最多 256 个条目和 8 MiB 序列化内容。较早的完整文件改动继续从 Codex 历史按需读取。
- 完整关闭和 RPC 断线清理 plan/diff、Token 缓存。淘汰、归档或删除会话时清理该会话的设置、用量、图片／文件授权和子代理详情；防止重复提交审批的标记保留原有生命周期。
- 仅在等待开始回复时暂存抢先到达的完成通知，回复处理结束后回收，兼容开始及完成通知都早于回复的情况。
- 官方桌面 IPC 原始状态按字符串、对象及数组槽位估算占用，单会话预算 32 MiB，全部会话预算 128 MiB。预算不是 Agent 进程的总内存上限；网络缓冲、解析、隐式共享分离和 Codex 子进程分别占用内存。

官方补丁依赖原始数组位置和 revision，所以超出预算时停止订阅并释放该会话的原始状态，保留限额标记以免反复订阅。默认自动模式使用现有的有界只读 RPC 同步及历史分页，不调用 `thread/resume`。手动选择“仅官方桌面”的会话会标为暂不可操作，需要使用自动模式以继续读取超大历史。此处理不删除 Codex 的本地历史，不终止正在运行的任务。

“用户查看后”不作为服务器端的销毁确认：多个客户端可能先后连接。近期预览保持有界，旧轮次和被淘汰会话及时释放。

2026-11-16 进一步定位到官方桌面 v13 与 Agent 的 v11 检查冲突：拒绝快照后立即重新订阅，空闲时也会不断传输、解析完整会话。Qt 源码现已兼容 v13，并对未知版本及重复补丁恢复设置停止条件。现场证据、隔离对比和构建／安装范围见[官方桌面 v13 同步与空闲资源增长](agent-desktop-ipc-v13.md)。

## iOS 返回前台

共享移动客户端忽略临时 `inactive` 状态；iOS 控制中心、授权弹窗等不会强制重连。只有进入 `background` 才暂停连接，立即取消认证／健康检查超时、定时刷新和重试，并使旧 socket、票据及初始化回调失效。返回 `active` 后建立一轮新的恢复流程，保留已有会话内容。

空闲连接检查继续兼容现有服务器协议：使用一次有界订阅重放确认连接。健康检查不与正在进行的同步重叠；静默重放不反复展示“同步中”。认证与健康检查使用独立的超时；收到重放进度后，等待下一帧的期限延长到 60 秒，避免较慢但正常的重放被 12 秒首响应期限切断。完全无进度的同步仍会恢复连接。

## 两条消息记录与升级

此前临时消息变为已接受消息时，官方 item ID 会变化，协议中的 `clientMessageId` 用于把它们合成一次发送。需要服务器、Agent 和客户端都包含该支持。

2026-11-15 本轮只读检查确认线上服务器为 0.3.66。本机当时安装的 Agent 显示 0.2.39，二进制不含 `clientMessageId`；包含该修复的源码此前也仍使用 0.2.39。新版本 0.2.40 用于区分。此前生成的 Android 0.1.23 / 27 已包含客户端合并；iOS／桌面 Control 需按最新源码重新构建，不能仅凭客户端保留的旧显示版本判断是否包含修复。
